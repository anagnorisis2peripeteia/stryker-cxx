# Running `--mode clang-ast` on real code

`--mode clang-ast` parses each source file with **libclang** (the `libclang` pip package's
bindings) instead of the token heuristics, giving precise AST source ranges. It is optional and
gated by `pip install libclang`. The single most common pitfall is a **libclang/compiler version
mismatch**, which surfaces as a cryptic parse error such as:

```
error: clang parse failed for foo.cpp: 'stdarg.h' file not found
error: ... use of undeclared identifier '__builtin_...'
error: ... didn't find libc++'s <stddef.h> header. header search paths ...
```

These are not code bugs. They mean the libclang the bindings loaded does not match the clang that
produced `compile_commands.json`, so its builtin/standard headers and intrinsics don't line up.

## Requirements

1. **A `compile_commands.json` with the real build flags** for each file. libclang parses with the
   flags you give it (it does not re-run your build system), so the entry must carry the include
   paths, `-std`, sysroot, and defines the file actually compiles with. Generate it from your build
   (`cmake -DCMAKE_EXPORT_COMPILE_COMMANDS=ON`, `bear -- make`, `ninja -t compdb`, …) — not by hand.
2. **A libclang whose version matches that compiler.** `pip show libclang` must line up with the
   `clang --version` that built the compile database. Mixing versions (e.g. pip libclang 18 against
   Apple clang 21, or against Homebrew LLVM 22) breaks builtin headers and `__builtin_*` intrinsics.
   Pin them together, e.g. `brew install llvm@18 && pip install "libclang==18.*"`, and generate the
   compile database with that same `clang++`.

On stock macOS the Xcode `clang` is an Apple fork with no matching upstream pip `libclang`, so a
matched **Homebrew `llvm@<N>` + `pip install libclang==<N>.*`** toolchain (and a compile database
generated by that `clang++`) is the reliable setup; the token path (`--mode token`, the default)
needs none of this and carries the broad language coverage.

## Fallback

If a matched libclang isn't available, use `--mode token` — it is the default and requires no
libclang. clang-ast is the precision path for ambiguous rewrites when the toolchain is present.
